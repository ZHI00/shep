# 安装说明（未签名构建）

这个 `shep.dmg` 没有 Apple 开发者签名，也没有经过公证。macOS 会拦截它 —— 这是系统对所有未签名应用的默认行为，与应用本身是否安全无关。下面是放行的方法。

## 安装

1. 双击 `shep_0.7.1_aarch64.dmg`
2. 把 **shep** 拖进 **Applications**
3. 首次打开会被拦下，按下面任一方法放行

## 放行方法

### 方法一：系统设置（推荐）

1. 双击 shep，会弹出「无法打开，因为 Apple 无法检查是否包含恶意软件」，点**完成**
2. 打开 **系统设置 → 隐私与安全性**
3. 往下滚到「安全性」，会看到一行 *"已阻止使用 shep..."*，点旁边的 **仍要打开**
4. 再次确认，输入密码

之后正常双击即可，不用重复这个过程。

> macOS 15 (Sequoia) 起，Apple 移除了旧的「右键 → 打开」绕过方式，必须走系统设置这条路。

### 方法二：终端命令

如果嫌上面麻烦，装好后执行一次：

```bash
xattr -dr com.apple.quarantine /Applications/shep.app
```

这条命令移除的是「从网络下载」的隔离标记。执行后直接双击就能开。

## 系统要求

- **Apple Silicon 芯片（M1 及以上）** — 这个包只含 arm64，Intel Mac 无法运行
- macOS 版本需支持 Tauri v2（macOS 10.15+）

## 关于自动更新

这个构建**移除了自动更新功能**。原版 Shep 会检查上游仓库的更新，而这是一个定制版本 —— 保留自动更新会导致它被上游版本覆盖，定制内容全部丢失。所以更新只能靠重新分发新的 DMG。

## 为什么会被拦截

让 macOS 不拦截需要两样东西，都要求 Apple 开发者账号（99 美元/年）：

1. **Developer ID 证书** — 给应用签名，证明来源
2. **公证（Notarization）** — 把应用提交给 Apple 扫描，通过后盖章

这个构建两样都没有，所以走 ad-hoc 签名（只保证应用没被篡改，不证明来源）。功能上和签名版完全一致，区别只在首次打开需要手动放行。
